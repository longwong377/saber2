# V15 — the player's list, grouped, and what it does to Shark

Written 4 Sep, from the player's V15 notes, while Shark is mid-build. The
notes are a stream of consciousness and say so; this is them sorted into work,
with the one thing that matters most stated first: **most of this list lands on
the station**, so `SHARK.md` changes rather than waits.

The amendments to `SHARK.md` are at the bottom (§16), because §15's rule —
*"a place not in §3.2 is not built"* — means a new place has to be added to
that file before it can exist, and the player is the only authority that can
add one.

---

## 0. What is already true, so it is not re-asked for

Answering the notes' own "I have not played the game so I cannot know if you
have already built this":

- **The player has a home on the station.** `#27 Your cabin` on deck 44 — two
  rooms, a real window, a saber stand, a trophy wall, the campaign map table,
  a bunk, a desk, a wardrobe. It is built and standing. What V15 asks for is
  much more than it currently is; see §2.
- **The companion habitat exists.** `#28 The Kennel habitat` — a high room
  with a mezzanine, straw, perches, a pool, a run onto the arboretum, and a
  plaque for every companion that died. Every `Kennel` record gets a body.
- **Companions already have distinct abilities.** Twelve kinds, twelve verbs,
  a rung ladder, and `CompanionLife`'s beats between actions. What is NOT
  there is the thing V15 actually asks for — **growth you can see** — see §4.
- **The lift already connects the hangar to the station** and is the only
  door. What is not seamless is the world REBUILD between them; see §1.5.
- **All fifteen station species are in**, with bodies, names, jobs, rhythms
  and homes. The Borz cast has manifest rows and is not yet spawned; see §1.4.

## 1. THE STATION IS THE HOME — folds into Shark now

### 1.1 Name your station

One string in `Session`, set once, shown everywhere the station names itself:
the Arrivals departures board (#7), the lift readout's caption, the tram
platform signs (#40), the Databank's station page, and the PA. Default is a
name, not blank — an unnamed station reads as a bug, not a prompt.

Where you set it: the Databank terminal (#13) and the plan table in your own
cabin. Cost: small. Do it early — it is the cheapest thing on this list that
makes the place yours.

### 1.2 The leaderboard, as a place you visit

The note is honest that there is no picture of it yet, so here is one.

**#56 THE STANDING** — deck 40, off the Concourse's east gallery, opposite the
Databank. A tall narrow hall with a single object in it: a black obelisk three
decks high, running up through a cut in the soffit so you see the top of it
from the Living deck's balcony and the whole of it from the Concourse floor.
The names are cut into it, best at the top, and the whole column turns very
slowly. Your own row is lit; everyone else's is engraved.

Why an obelisk and not a screen: a screen is a menu with a wall behind it. A
thing you walk round, that is taller than the room it is in, and that you can
see from two other decks is a landmark, which is what §3.1 rule 1 says the
station needs more of.

- **What it ranks** is not one number. Four faces, one per axis, because a
  single "score" is the thing nobody can chase: waves survived, longest run,
  most saved (the company's living roll), and deepest campaign.
- **It persists** in the same `Session` fold the ledger already uses, and a run
  that betters a row cuts it in on the spot — you see it happen if you are
  standing there when a run files, which is the reason the run-filing happens
  on the station at all.
- **The dead are on it too.** The memorial roll (#45) and this share a source;
  a name that comes off the company goes onto the obelisk's fourth face.

### 1.3 The home, made yours — the big one

V15 wants `#27` to be a game within a game: furniture, colours, kitchen, rooms,
decor, a mirror, a place for smaller companions, a unique address, windows onto
the real battle, and all of it saved so it survives a death.

That is a system, not a room, and it splits into five:

1. **A grid and a catalogue.** The cabin's floor is a placement grid; the
   catalogue is `Props.Kit` pieces plus the station's own furniture, each with
   a footprint. Place, rotate, remove. Everything placed is a real `Prop`
   body, so a home is still a sandbox — you can knock your own furniture over.
2. **Surfaces.** Wall, floor, trim and light colour, per room, off the same
   palette discipline `DECK_PALETTE` uses, so a cabin cannot be made to look
   like it is from another game.
3. **Rooms.** The cabin is two rooms now. Make the partition movable and let a
   third be unlocked — the address (§1.3.4) is what pays for it.
4. **An address.** `44-C-17` and so on, derived from the deck, the sector
   angle and the door number, printed on the door and on the notice board
   (#25). It is what makes a home a place rather than a menu.
5. **Persistence.** Its own `Session` fold, saved on leaving, never touched by
   a death. The note is explicit: *"you would have the option of saving it so
   you don't lose all the work if you die"*.

**The window is the real one.** §3.1 rule 5 already says every place has a
window onto another place; the cabin's looks at space, and V15 wants it to be
the same space the hangar looks at — the last theatre you selected, with its
battle. `enterStation` already hands the world `_pickedLevel` through the same
resolver the deck uses, so this is the `SkyDome` the deck already builds,
outside the cabin's glass.

**The mirror is the customiser.** A real mirror in the cabin, and standing at
it opens the character creator with your own body in the glass rather than on
a menu stage. The note's eventual intent — that this becomes the ONLY place you
customise — is right, and the way to get there without breaking anything is to
leave the menu's page working and make this a second door onto the same panel.
Removing the menu's is a later, separate change.

**Small companions at home.** The kennel (#28) is where the big ones live; a
cabin gets a perch, a basket or a charge pad for one small companion, and which
one is a choice you make at the habitat.

### 1.4 The whole cast, mixed

V15: the hangar's droids and NPCs mixed in with the fifteen station species,
*"not in jedi clothes obviously they would have to have unique non jedi
clothing"*.

`StationCast.BORZ_RESIDENTS` is already the manifest — clone crew, medics,
Jedi, a Sith acolyte drinking alone, a Wookiee smith, astromechs, a
reprogrammed B1, bodyguards, a Geonosian, and three rows that decline with a
reason. What is missing is two things:

- **They are not spawned yet.** `StationLife`'s pool draws from the species
  table only. The manifest has to be a second source the pool draws from, at
  the places each row names.
- **Off-duty dress.** A trooper on the station is not in a trooper's plates and
  a Jedi is not in robes. Every Borz row needs a civilian costume through the
  same `robe` override the fifteen species use, so it is a palette and not a
  new body. That is the whole cost.

### 1.5 No loading screen between the hangar and the station

V15: *"seamlessly should be able to go from our star wars hangar to the station
through just the elevator with no loading screens … should feel like just going
to a different place, not two separate games."*

Today the lift ride is 5.5 s and the world is torn down and rebuilt inside it.
The ride is already the right length to hide a load — what gives it away is
the loading plate appearing over the top. Three moves, in order of what they
buy:

1. **Do not show the plate.** The ride is a scene; build behind it and let the
   doors open on the new deck. The lift's own shaft scene is what the player
   is looking at, and it is the same car either side.
2. **Keep the rooms decoded.** `StationMesh`'s cache is session-lived already,
   so a second visit decodes nothing.
3. **Only then** consider keeping both worlds alive, which is the expensive
   answer and probably never needed.

### 1.6 The Starfury sees the hangar

V15: fly to the flight deck, see it through the force field, watch ships come
and go, and not be able to enter.

§4 already has *"fly past your own hangar and look into it — `DeckExterior`
already maps the aperture, and the deck's lit interior is visible through the
field"*. V15 adds two things: the traffic keeps running while you watch, and
the field is solid to YOU. Both are small once `LEVELS.orbit` exists.

## 2. THE PLAYER'S BODY — its own lane

V15 asks for: a woman of any Star Wars species, obviously so; attractive and
SFW; sliders for chest and glutes with real bounce; hair with real physics;
women's outfits; men able to go shirtless; clone armour head to toe, with or
without helmet, capes and waist capes over it.

Notes on doing this well rather than badly:

- **It is the creator's table, widened.** `Bodies.js` already has seven
  species, eight face axes, a build parameter and a muscle parameter, and
  `buildJedi` already takes them all. A sex axis is another row-level
  parameter, not a second body.
- **The physics is `Cloth.js`'s.** The engine already simulates a cape and
  lekku with a real solver, and hair and soft-body bounce are the same solver
  with different anchors and stiffness. Nothing new is needed, which is also
  what keeps it tasteful: it is secondary motion at the amplitude the slider
  says, damped, and it stops when you stop.
- **Armour is `Armour.js` + the company's kit tables.** The clone kit already
  exists as parts with slots. What is missing is letting the PLAYER wear the
  set the company wears, which is a slot list and a menu page, not new
  geometry.
- **The capes already exist** (`attachTrooperCape`). A waist cape is one more
  anchor row.
- **Where it is done:** the mirror at home (§1.3), and the menu page until
  that is proven.

Order: sex axis and outfits first (it is the ask), then armour slots, then the
secondary motion, then the shirtless/capes tail.

## 3. MELEE — kicks and punches, and a reason to lose the blade

V15 is precise about what it wants and, importantly, about what it must not be:

- Kicks and punches, kung-fu inspired, *"make it look really cool"*.
- For players who want to fight without a saber, or who have lost it.
- **Not nearly as strong as the blade**, and it does not cut.
- **Blunt damage**, so the physics has to read as blunt: **noticeable
  knockback**, no dismemberment, no slice.
- **More stamina** per swing than a saber attack.
- **Upgradable through the Holocron** to be genuinely effective.

That last clause is the one that makes it a system rather than a fallback. The
Living Force tree is where the player's power comes from; a melee branch on it
is what makes "run melee and Force powers" a build rather than a handicap.

What it needs:
- A strike set on `SaberController`'s input path with no blade lit — three or
  four moves that chain, with the pose work in `Rig.js` where the gait already
  is.
- Impulse rather than a cut: `Impact.js` is already the door for a striker,
  and a knockback is an impulse with a stagger, both of which exist.
- Stamina: the drain table is in `Player.js` and has a row per action already.
- A Holocron branch: `LivingForce.js` is a table of facets, so it is rows.

It is self-contained and it is the single biggest change to how the game plays
on this list. Worth doing early.

## 4. COMPANIONS — growth you can see, and a reason to use the station

V15's question, answered plainly: **the abilities exist, the growth does not.**
Twelve kinds have twelve verbs, a rung ladder and a permadeath that already
matters. What is missing is everything that makes you attached:

- **It changes shape.** A companion that has survived four runs should be
  visibly bigger and visibly different, and an inorganic one should have
  visibly more hardware — plating, a second arm, a bigger dish. The body
  builders are parameterised by scale already; what is missing is a growth
  parameter on the `Kennel` record and a few kind-specific attachment rows.
- **Growth is not only battle.** V15 asks for the Palworld/Pokémon half:
  care, feeding, grooming, play, at the habitat, ON the station, between runs
   — and for some rungs to need BOTH. That is the whole reason it makes the
  station load-bearing rather than decorative.
- **A management screen, reached only at the habitat.** Not a menu tab. You
  walk to #28, and each companion's own place in it is where you manage that
  companion.
- **Drawbacks too.** V15 asks for them and is right to: a companion that only
  ever helps is a stat. A big one is slow and loud; a bonded one panics when
  it is hurt.
- **And then it dies.** All of the above is in service of the permadeath
  already in the game meaning something.
